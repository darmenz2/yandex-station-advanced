# Yandex Station Advanced

Неофициальное приложение для передачи звука Windows на Яндекс Станции по локальной сети.
Текущий импорт — **2.0.0-preview.5**; основной транспорт — WAV/PCM, резервные варианты — MP3/HLS.

> **Это нестабильная экспериментальная версия. Треск, прерывания звука и рассинхронизация
> между колонками остаются нерешёнными. Импорт исходников не является исправлением этих проблем.**

## Что работает в коде и что ещё не подтверждено

В исходниках реализованы авторизация Яндекса, обнаружение устройств, захват системного звука
через WASAPI, управление из меню Windows и локальной веб-панели. Есть группировка колонок,
назначение левого/правого канала, экспериментальное разделение низких частот и калибровка.
Наличие реализации **не означает**, что воспроизведение стабильно на конкретной прошивке Станции.

По результатам пользовательских испытаний сохраняются слышимый треск, заикания и паузы;
колонки могут играть с разной задержкой и постепенно расходиться. Встречались также
одновременное приглушение и пропадание отдельного канала. Причины всех этих проявлений
не установлены, подтверждённого общего исправления нет.

В preview.5 менялась обработка очереди PCM и отключались некоторые экспериментальные
коррекции темпа. Это изменения реализации, **не доказательство устранения слышимых дефектов**.
Общий поток отсчётов и состояние «Получает PCM» не подтверждают одновременное воспроизведение
разными колонками. Блок PCM 10 мс — размер передаваемого блока, а не измеренная сквозная задержка.

Режим «музыка везде» и проверка уже созданной штатной стереопары отделены от независимых
Windows-потоков. Проект не заявляет, что воспроизводит внутренний механизм синхронизации Яндекса.
Работа физических Станций, радиосети, микрофона и WASAPI в ходе этого импорта не проверялась.

## Запуск из исходников

Для приложения предназначена Windows x64. Исходный комплект ориентирован на Python 3.13.
Из корня репозитория в PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe advanced_entry.py
```

Далее выполните вход, выберите устройства и запустите передачу в интерфейсе приложения.
Начинать диагностику лучше с одной колонки без разделения каналов, затем отдельно проверять группу.

`Run.cmd` — альтернативный запуск через прилагаемый `bootstrap.ps1`: при отсутствии компонентов
он подготавливает приватную среду Python и загружает зависимости. Личные токены и настройки
в репозиторий не включены. Не публикуйте `account.dpapi`, `settings.json`, ссылки панели с `#key=`
или диагностические выгрузки без предварительной очистки.

Готовые EXE/DLL в Git не хранятся. Виртуальный аудиовыход не поставляется как собственный драйвер:
интеграция с VB-CABLE требует отдельной установки стороннего компонента и согласия пользователя.

## Структура

```text
advanced/                  Меню Windows, группы, обработка и калибровка
station_bridge/            Захват, авторизация, Glagol, HTTP и потоки аудио
web/                       Локальный веб-интерфейс
installer/                 Исходники установщика и сценарии сборки
assets/                    Значок приложения
licenses/                  Уведомления авторов исходных компонентов
reference/pcm-1.0.6/        Изолированный исходный PCM 1.0.6 для сравнения
tests/                    Тесты основной версии
tools/                    Проверка целостности импорта
docs/                     Описание импорта и архивные материалы
```

PCM 1.0.6 сохранён отдельно, чтобы сравнивать поведение и искать регрессии. Его наличие
не означает, что он полностью стабилен или решает треск/рассинхронизацию.
Не копируйте его `station_bridge/` поверх основного пакета и не объединяйте два набора тестов
в одном процессе Python.

## Сборка и проверки

Нативные компоненты собираются из C-исходников; требуются `clang` и `lld-link` в `PATH`.
Сценарий ориентирован на кросс-сборку и во время импорта проверяется в Linux, не запуском GUI Windows.

```sh
python installer/build_setup.py
```

Результат: `dist/`, лаунчер/деинсталлятор в корне и библиотека DSP в `advanced/native/`.
Сборка формирует `dist/payload.zip`, который нужен части тестов установщика.
Для полного набора тестов сначала выполните сборку:

```sh
python -m pip install pytest pytest-asyncio
python -m pytest tests -q
```

Набор PCM 1.0.6 запускается отдельно:

```sh
cd reference/pcm-1.0.6
python launcher_source/build_launcher.py
python -m pytest test_recovery.py -q
```

Контроль файлов импортируемого снимка не требует сторонних библиотек:

```sh
python tools/verify_source_import.py
```

Проверка сверяет импортированные файлы с `SOURCE_IMPORT.json`, а основной `LICENSE` —
с исходным Git-объектом. После дальнейшей разработки изменения относительно снимка
будут отражаться как несовпадения; это не тест работоспособности приложения.
Результаты текущих проверок и ограничения окружения находятся в [отчёте импорта](docs/IMPORT_VERIFICATION.md).
**Успешные модульные тесты, проверка файлов и компиляция не подтверждают отсутствие треска
или акустического дрейфа на физических колонках.**

## История и происхождение

Импорт основан на `YandexStationAdvanced_preview5_Source.zip` и
`StationBridge_PCM106_Recovery.zip`. Исходные файлы сохранены с проверяемыми контрольными
суммами; исключены готовые двоичные сборки и старые журналы проверок.
Полная карта включённых и исключённых файлов находится в `SOURCE_IMPORT.json`.

Четыре существовавших коммита `9874571` → `70581a4` → `5cdb4d6` → `f5144f9`
сохранены с исходными SHA. Импорт добавлен следующими коммитами, без переписывания истории.
Исходного Git-журнала разработки внутри ZIP не было: дополнительные «исторические»
коммиты задним числом не создавались.

Workflow в `.github/workflows/` сохранены как часть прежней подготовки импорта.
Для этого снимка они не нужны: исходники уже являются обычными файлами Git,
а не временными Actions-артефактами или неприкреплёнными фрагментами архива.

В [архивных материалах](docs/archive/README.md) сохранены прежние описания и манифест поставки.
Их формулировки о результатах относятся к прежней подготовке, не заменяют текущий статус выше
и не являются подтверждением исправления пользовательских жалоб.
