# Резервный запуск исходной Station Bridge 1.0.6

## Что сделано

Скопированы 13 Python-файлов исходного пакета `station_bridge/`, семь файлов
`web/` и уведомление лицензии из архива `StationBridge_1.0.6_PCM_Latency_Update.zip`.
Все 21 перечисленные файлы проверены SHA-256 и побайтно совпадают с источником.
Алгоритм захвата, PCM, HTTP, регулировка громкости и исходная панель не изменены.

Новый код относится только к отдельному запуску: поиск установленного private Python,
изоляция импорта приложения от папки Advanced, отдельная папка настроек,
подтверждаемый перенос только подключения/зашифрованного входа и локальное окно браузера.
Контрольная панель резервирует порт 8789 или другой свободный на 127.0.0.1.
Аудиопорт прежний 8808; при занятом порте чужой процесс не завершается.

## Почему не очередная «исправленная preview»

При сравнении кода 1.0.6 и preview.5 подтверждено, что это разные пути передачи:
в preview.5 появился `advanced/steady_stream.py`, общий старт группы, FIFO-получатель
и отдельные процессоры назначения каналов. В восстановленной копии этих модулей нет.
Сравнение кода не устанавливает, какой из изменений вызвал слышимое ухудшение
на компьютере пользователя. Актуального отчёта во время этого случая нет.

## Проверки этой поставки

11 проверок пройдены на Linux / Python 3.13.5:
- соответствие исходным файлам;
- отказ при изменённом файле и попытке выйти за папку через manifest;
- перенос только выбранных настроек, отсутствие перезаписи оригиналов;
- отказ от импорта и защита уже имеющейся копии;
- отсутствие приватного ключа панели в журнале;
- импорт именно движка 1.0.6;
- формат нового EXE: PE32+, AMD64, GUI;
- настоящий запуск localhost HTTP и штатное завершение, запрос без ключа отклонён,
  захват звука сам не включился. Вызовы перечисления аудиоустройств и сетевых
  адаптеров в этом тесте имитировались, браузер не открывался физически.

Прямая установка недостающего zeroconf в Linux-стенд не удалась из-за недоступности
сети. Реальный mDNS, поиск колонок и облачный вход на этом стенде не запускались.
Запускатель на компьютере пользователя использует его уже установленный zeroconf.

Не проверены: исполнение нового EXE на Windows, нативные диалоги/DPAPI,
WASAPI и звуковое воспроизведение через реальную колонку.
Акустическая задержка, синхронизация группы и устранение текущего заикания
этой проверкой НЕ подтверждаются.

## Сборка

`python launcher_source/build_launcher.py` — clang/lld-link, без SDK и драйвера.
Исходники запускателя и уведомление MIT включены. Runtime не входит в архив.

Справка по изоляции встроенного Python:
https://docs.python.org/3/library/sys_path_init.html#pth-files
Справка по запуску GUI-процесса:
https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags
