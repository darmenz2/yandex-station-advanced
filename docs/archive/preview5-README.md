# Yandex Station Advanced — 2.0.0-preview.5

Неофициальное приложение Windows x64. Нативное меню у часов, QR-вход в Яндекс,
WASAPI-захват, один источник PCM и отдельные HTTP-получатели для каждой Станции.
Основной режим — WAV/PCM с запрашиваемым блоком 10 мс. Сохраняются экспериментальный
PCM 1 мс и резервные MP3/HLS. Основа Glagol/авторизации — AlexxIT/YandexStation (MIT).

## Обновление

Завершите Advanced через значок у часов, запустите GUI-установщик preview.5 и оставьте
прежнюю папку `%LOCALAPPDATA%\Programs\YandexStationAdvanced`. `.runtime` не удалять:
исправные компоненты используются повторно. Вход, рабочие IP, подтверждённые
сертификаты и разрешения NAT сохраняются отдельно от программных файлов.

Установщик для текущего пользователя, онлайн. При отсутствии Python/зависимостей
загружает их с python.org/PyPI; подпись Python и контрольные суммы проверяются.
Сам EXE пока без подписи. Защиту Windows и Secure Boot отключать не требуется.
Установка и запуск Win32 GUI в среде подготовки не выполнялись — это preview.

## Одна, две или три колонки

Откройте значок → **Настроить 1 / 2 / 3 колонки**. При необходимости сначала войдите
по QR. Нажмите поиск, выберите схему, отметьте устройства, заполните позиции и нажмите
**Применить схему и запустить**. Каналы сохраняются все вместе. При первом подключении
сверьте IP и подтвердите сертификаты в этом же мастере.

Схемы:

- **Одинаковая музыка:** любое число выбранных Станций получает стерео целиком.
- **Одна колонка:** ровно одно выбранное устройство, без разделения каналов.
- **Стерео:** две разные колонки, явно назначенные слева и справа.
- **2.1:** Light 2 слева/справа, Midi — низкие частоты; стартовый раздел 120 Гц.
- **Низ / нижняя середина:** та же тройка с разделом 400 Гц. Это нижняя часть
  середины, не вся середина и не отдельный центр 5.1.

120/400 Гц — отправные настройки, не измеренный акустический оптимум. Используются
фильтры Linkwitz-Riley четвёртого порядка. В пресетах с басом постоянный запас уровня
−3 дБ на всей схеме, для баса дополнительно −3 дБ. Уровень и раздел можно изменить
в Advanced menu. Это статический уровень, не автоматическое приглушение музыки.

Если включено разделение, но у подключённой колонки нет роли, запуск теперь
отклоняется с её именем. Явная роль «Не играет» остаётся доступной в ручных настройках.
Повторное применение той же схемы сохраняет измеренные задержки и уровни.

## Кнопки и состояния

Сразу после нажатия видны название операции, этап и время ожидания. Повторная
одинаковая операция не создаёт второй запуск. Другие изменяющие операции не
накапливаются в очереди. «Остановить / отменить» доступно и при подключении.
Готовность, ошибка и запрос подтверждения остаются в меню; есть журнал действий.

Для каждой колонки показаны подключение, отсутствие назначения, ожидание HTTP,
ожидание группы, необходимость NAT-разрешения, чтение PCM, пауза или остановка.
«Получает PCM» означает действительный HTTP-приём, **не подтверждение слышимого
звука или акустической синхронизации**. У зависшей колонки есть отдельный повтор;
остальные не останавливаются. Если её Glagol разорван, повторите настройку системы.

## Непрерывность PCM: исправление заиканий

Обычный WAV/PCM запрашивает блоки 10 мс. Ранее основной путь мог отбрасывать
целые корректные пакеты после задержки обработки более 60 мс, а каждому HTTP-
получателю назначался свой таймер и регулятор темпа. Это риски реализации;
они не объявляются доказанной причиной конкретного случая на колонках пользователя.

В preview.5 обычный PCM использует FIFO исходных отсчётов: без пересчёта частоты,
без отдельного таймера темпа на каждую колонку, без намеренного пропуска кратко
задержавшихся пакетов. Изменение скорости ±0,2% вынесено в явный эксперимент
и выключено при первом запуске этой версии, даже если было включено в preview.4.

Раздел **Защита от заиканий и состояния** содержит стартовый резерв
**80 / 120 / 200 / 300 мс**, по умолчанию 120 мс. При первом запуске этот резерв
накапливается и отправляется Станции, затем следуют новые кадры источника.
Он не удерживается постоянно перед каждым HTTP-блоком. Это намеренно более
осторожный старт, не обещание общей задержки 120 мс и не управление буфером ЦАП.
Для смены резерва сначала остановите трансляцию.

Первый запуск группы ждёт первые HTTP-запросы, максимум 1,5 секунды, и выбирает
общую исходную позицию. После этого каждый получатель получает свои отсчёты
по порядку. PCM-очередь захвата сохраняет кратко задержавшиеся пакеты; её предел
возраста 2 секунды — аварийное ограничение хранения, а не добавленный звуковой буфер.
Обычный режим не вставляет тишину лишь потому, что callback задержался на 50–150 мс.
При отсутствии входных данных дольше 250 мс выдаётся цифровая тишина для сохранения
соединения. Это не восстановление утраченной музыки: большие отказы источника
или радио могут оставаться слышимыми.

Плановые и послетишинные сбросы всей PCM-группы отключены. Нажатие «К живому звуку»
в обычном FIFO не включает скрыто изменение скорости и не пересоздаёт соединения.
Кнопка не обещает очистить уже накопленный внутри Станции буфер. Ограниченное
восстановление оборвавшегося получателя сохранилось; оно может быть слышимо.

Сохранённые назначения Left/Right/Midi, уровни и фильтры применяются как прежде.
Медленный получатель не блокирует остальных. Если история кольца действительно
перезаписана, фиксируется пропуск исходных отсчётов и смягчается граница —
не скрывается ошибка под нулевым счётчиком и не заявляется восстановление данных.

**Это улучшение Windows-передачи, а не копия штатной синхронизации Яндекса.**
Нулевой счётчик пропусков PCM и совпадение файла с эталоном не доказывают отсутствие
акустического дрейфа на разных колонках.

## Штатный механизм Яндекса

В меню добавлен отдельный пункт **Штатный Яндекс · музыка / стереопара**.
Обычный WAV/PCM и штатные механизмы не объединены под одним обещанием.

### Музыка Яндекса на всех колонках

Кнопка **Яндекс Музыка · включить везде** после подтверждения останавливает
Windows-захват и передаёт одной подключённой Станции команду
«включи музыку везде». Дальше воспроизведением управляет прошивка Яндекса.
Область команды — **все колонки дома, включая невыбранные в Advanced**;
перед нажатием это явно подтверждается. Это не трансляция YouTube/Spotify/Windows,
не сохранение выбранного на ПК трека и не назначение Миди отдельным басом.
Состояние означает «команда отправлена», а не автоматически «всё слышно».
Для завершения есть «Остановить штатную музыку». При потере связи приложение
не утверждает успешную остановку и не мешает закрыть локальную программу.

### Проба Windows через уже созданную стереопару

Пару сначала создаёт владелец в приложении «Дом с Алисой»: две Лайт 2,
выбор левой/правой и главной. В официальной справке предупреждается:
**на ведомой сбрасываются настройки и сценарии, после разъединения они
не восстанавливаются**. Advanced не создаёт, не разбирает и не перенастраивает
пары автоматически. Ссылка на справку открывается только явной кнопкой.

Далее нажмите **Проверить конфигурацию пары**. Приложение принимает только
взаимно согласованные роли главной/ведомой и ID партнёров в ответе аккаунта;
отсутствующие поля обозначаются как неизвестные, главная не угадывается по имени.
Подключите главную через схему «Одна колонка». Кнопка
**Проверить PCM только через главную** запускает полный стереопоток только ей,
без независимых команд второй Лайт и без Миди. Конфигурация перед запуском
перечитывается. Тест доступен только для подтверждённой пары.

**Передача локального WAV ведомой колонке — пока проверка совместимости на
вашей прошивке, а не заявленная готовая функция.** Если играет только одна,
программа не включает скрыто второй несинхронный поток и не пишет «пара работает».
Она не меняет ACL аудио на открытый для всей сети. Новые адреса источников
HTTP-запросов, если появятся, требуют прежнего явного подтверждения.

Схема «Лайт слева + Лайт справа + Миди только для баса» остаётся отдельной
программной обработкой. Штатное подключение Миди в качестве сабвуфера к двум
Лайт в этой сборке не реализовано. Настройка одинаковых ролей по документации
не равнозначна доступу к аудиочасам прошивки.

### Наблюдения вместо предположений

В диагностику добавлена ограниченная расшифровка присутствующих полей AppState:
состояние проигрывателя, переданные временные позиции, признак аудиофокуса,
роль мультирума и хеш идентификатора часов. Чтение ограничено размером и числом
полей. Токены, ссылки контента и сырые сообщения прошивки не сохраняются.
Наличие clock_id не выдаётся за право задавать эти часы или за подтверждение
синхронности. Максимум 120 последних наблюдений на колонку, до двух в секунду.

## Микрофон

Advanced menu → Микрофон. Запускается только с явного подтверждения, выдаёт по три
сигнала на колонку, измеряет относительную задержку и предлагает задержать более
быстрые устройства до самой медленной. В этой версии тест использует тот же общий
старт и непрерывный HTTP-тракт; фильтры баса для теста обходятся. Результат применяется
отдельной кнопкой. Микрофон после замера/отмены освобождается; записи не сохраняются.

Это не постоянное прослушивание и не коррекция дрейфа ЦАП в реальном времени.
Повторный запуск потоков, изменение сети и прошивок могут изменить задержки.
Автоматический комнатный эквалайзер и фазовая калибровка сабвуфера не заявлены.

## Одновременное приглушение

Программа не добавляет AGC или периодическое изменение громкости. В новом тракте
нет планового сброса всех колонок. Если уровень всё равно падает на всех одновременно,
нужна диагностика во время случая: проверьте источник Windows, состояния Алисы и сеть.
Windows умеет уменьшать громкость при сеансах связи. В меню есть кнопка открытия
классического «Звука»; вкладка «Связь» содержит соответствующий выбор. Программа
глобальную настройку сама не меняет. Наблюдение максимального уровня 1,0 в старом
отчёте само по себе не доказывает причину искажений.

## Виртуальный выход и безопасность

Необязательный VB-CABLE устанавливается своим оригинальным мастером после согласия.
Драйвер не включён в наш EXE. Только отдельные действия установки/переименования
драйвера требуют UAC. Выберите выход «Яндекс станция» в Windows самостоятельно.

Панель управления остаётся на localhost с ключом и проверками Host/Origin.
Native flyout не открывает браузер. Аудио — незашифрованный HTTP в доверенной LAN,
со случайной ссылкой и точным ACL Станции / подтверждённого NAT-адреса. Сертификаты
Glagol закрепляются после явного подтверждения. Токены не входят в диагностику.

## Исследование штатной стереопары

В официальной справке Яндекса пара описана для двух колонок с одинаковыми звуковыми
характеристиками. В публично извлечённых protobuf-описаниях прошивки есть роли
leader/follower, идентификатор и адрес сетевых аудиочасов, базовое время и позиция.
Это свидетельствует о более полном механизме синхронизации, чем одновременные
независимые HTTP-плееры. Эти описания не являются публичным поддерживаемым API и
не доказывают готовую возможность управлять такими часами с ПК. Их код в приложение
не копируется; произвольные команды создания штатной пары не отправляются.

## Проверка и сборка

Python 3.13, clang, lld-link. `python installer/build_setup.py` собирает нативные x64
GUI EXE и DSP DLL без обращения к сети. `python -m pytest -q` запускает тесты
(нужны pytest/pytest-asyncio и библиотеки приложения). Нативные Windows-сценарии
проверены по исходникам/компиляции, не реальным запуском. Долговременная проверка
делается через настоящий localhost HTTP и искусственный PCM, не через физические
Станции. Полные результаты конкретной поставки — в отдельном отчёте.

Лицензия MIT, исходные уведомления в `licenses/`. Это неофициальный проект,
не связанный с Яндексом или VB-Audio. Репозиторий GitHub этой поставкой не изменяется.
